# 定图纸开关偏好记忆 · 需求文档

> 状态：已实现（2026-11-05）
> 实现现状见：docs/功能规格/拼豆图纸生成器.md
> 讨论日期：2026-11-05
> 文档职责：回答「为什么这么做」——场景、范围、方案对比、决策记录、验收标准。本文件已冻结，仅在有追加需求时新增章节。

## 0. 一句话场景

一个习惯固定关掉若干转换开关的用户，每次重新打开「豆格」生成图纸时都要把「3 · 定图纸」里相同的开关再关一遍；他希望开关的开/关被记住，下次直接沿用。

## 1. 数据流

- 来源：用户在「3 · 定图纸」里主动切换 7 个开关，产生 `onParam({开关字段: 值})` 或 `onLockRatio(值)`。
- 节点：切换动作 → `App.applyConfig` / `changeLockRatio` → 从当前 `params` + `lockRatio` 提取布尔偏好 → `localStorage`（key `wedou.toggle-preferences`）→ 下次页面初始化时读出 → 与 `DEFAULT_PARAMS` 合并成初始 `params`，`lockRatio` 单独恢复。
- 空值：没有存储记录（首次使用）→ 全部字段取 `DEFAULT_PARAMS` / `lockRatio=true`，与改动前出厂行为一致。
- 异常：存储被禁用、配额超限、内容不是合法 JSON、字段类型不对或字段缺失 → 逐字段回退出厂默认，不抛错、不白屏；写入失败只丢失「记忆」这一附加能力，页面功能照常。

## 2. 状态机

- 状态：`未记录`（首次）→ `已记录`（用户切换过至少一次开关）→ `已记录`（后续切换持续覆盖）。
- 出口：没有「清除偏好」入口；用户想恢复出厂值就手动把开关拨回去，拨回本身也是一次记录。
- 互斥与并发：开关彼此独立；快速连点只会重复写同一份快照，最后一次为准。多标签页并行操作时后写者覆盖前者，不做跨标签实时同步（见边界）。
- 恢复只发生在**页面初始化**，不在上传图片、打开图纸、生成图纸时重放，避免覆盖用户当前这一轮的选择。

## 3. 影响面

- 新增 `src/core/preferences.ts`（偏好类型、提取、合并、读写与校验）、`tests/preferences.test.ts`。
- 修改 `src/App.tsx`：初始化 `params` / `lockRatio`、`applyConfig` 中持久化、`onLockRatio` 包装；其余 handler 不动。
- `src/views/StudioView.tsx` 的开关 UI 与 `onParam` 接口不变；`src/components/ui.tsx` 的 `Toggle` 不变。
- 下游 `quantizeImage` / `optimizeGrid` / 三种导出都只读 `params`，不受影响；`Pattern` 公共契约、`server/*`、渲染层均不改。
- 文档：`docs/功能规格/拼豆图纸生成器.md`（活文档）、`README.md` 功能列表。
- 已有功能风险点：`openPattern()` 会用工程文件自带的 `params` 整体覆盖当前参数。若把偏好做成无条件监听 `params` 的副作用，打开旧图纸会反向改写全局偏好，把用户之前关掉的开关重置回来——必须避免。

## 4. 边界与失败

| 情形 | 行为 |
|---|---|
| 首次使用 / 无记录 | 全部开关为出厂默认，页面表现与改动前一致 |
| 上传新图 | 只重置并推荐宽高；开关沿用上一轮（含刷新前记住的偏好） |
| 打开图纸库里的旧图纸 / 导入工程文件 | 开关显示该图纸保存时的值，不被全局偏好篡改；此后用户手动切换才写入偏好 |
| 存储内容缺字段 / 字段是字符串或 null / 是数组 / 是坏 JSON | 逐个字段回退出厂默认，合法字段仍生效 |
| 隐私模式、禁用 localStorage、写入配额超限 | 静默降级为「不记忆」，不报错、不阻塞生成图纸 |
| 多标签页同时改开关 | 后写者覆盖；不做 `storage` 事件同步，避免引入跨标签状态抖动 |
| `detailPreserve` 在旧工程里为 `undefined` | 视为「开」，与现有 UI 的 `!== false` 判定一致 |
| `backgroundTolerance` 是数值 | 偏好只存布尔 `autoBackground`；恢复时开→`DEFAULT_BACKGROUND_TOLERANCE`、关→`0` |

## 5. 方案对比

| 方案 | 做法 | 优点 | 不选的原因 / 取舍 |
|---|---|---|---|
| A 整个 `ConvertParams` 直接存取 | 把 `params` 整个 JSON 存进 localStorage，初始化时直接替换 | 代码最少 | 会把宽/高/最多颜色数也记住，破坏「按每张原图比例推荐尺寸」；旧数据还可能带非法数值污染转换链路 |
| **B 只存 7 个开关的布尔快照（选中）** | 新增纯函数模块做提取/合并/校验，初始化时与 `DEFAULT_PARAMS` 合并 | 尺寸仍按图重算；字段级校验、可单测；不上云、不涉隐私外传 | 比 A 多一个模块和约 6 处接线 |
| C 跟随账号云同步 | 后端加偏好字段 + API | 跨设备一致 | 需要登录、改动后端与 DB、把使用习惯上传；「不登录也能完整使用」的项目基线会被破坏，收益与本次痛点不匹配 |

选 B：付出一个可单测的纯函数模块，换来「记忆的只是偏好、不是某张图的尺寸」这一语义正确性，以及脏数据不会破坏转换链路。

## 6. 决策记录

| 编号 | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 记忆范围 | 仅「3 · 定图纸」7 个开关：锁定原图比例、透明区留空、自动抠纯色背景、去掉孤立单颗豆、合并小色块、保留细线细节、色彩抖动 | 用户原话是「开关的开启和关闭」；宽高由原图比例决定、最多颜色数是滑块，都不属于偏好 |
| D2 | 存储 | `localStorage`，只存布尔旗标，不随账号、不上云 | 与「图片不出浏览器 / 云端只存图纸数据」的隐私基线一致，不登录也可用 |
| D3 | 写入时机 | 仅用户主动切换开关时写；上传新图、打开图纸、改尺寸都不写 | 避免打开旧工程文件时反向覆盖用户偏好 |
| D4 | 恢复时机 | 只在页面初始化时合并进 `DEFAULT_PARAMS` | 保证一轮工作内的临时改动不被反复重放 |
| D5 | 与工程文件冲突 | 图纸自带 `params` 优先，全局偏好不覆盖 | 工程文件要可复现，全局偏好只用于「新建图纸」的起点 |
| D6 | 校验策略 | 逐字段只接受 boolean，其余回退出厂默认；读写全程 try/catch | localStorage 是用户可改的不可信输入 |

## 7. 验收标准

1. 用户打开页面 → 关掉「去掉孤立单颗豆」和「色彩抖动」→ 刷新页面 → 这两个开关仍是关闭，其余开关保持原状态。
2. 用户关掉「透明区留空」→ 上传一张新图片 → 该开关仍关闭，宽高显示按新图比例重新推荐的数值，而不是上一张图的尺寸。
3. 用户在图纸库打开一张旧图纸 → 开关显示该图纸保存时的设置，不被自己的偏好改写；随后手动关掉某个开关 → 再新建图纸时该开关保持关闭。
4. 用户用无痕窗口打开页面（或手动写入坏 JSON 到 `wedou.toggle-preferences`）→ 页面正常显示、开关为出厂默认、控制台无报错，仍能生成图纸。
5. 用户打开页面 → 反复切换任一开关 → 控制台无报错，生成图纸结果与该开关的当前状态一致。
