# 拼豆图纸生成器 · 需求文档

> 状态：已实现（2026-11-05）
> 实现现状见：docs/功能规格/拼豆图纸生成器.md
> 讨论日期：2026-11-04
> 文档职责：回答「为什么这么做」——场景、范围、方案对比、决策记录、验收标准。本文件已冻结，仅在有追加需求时新增章节。

## 0. 一句话场景

一个手里有某品牌拼豆和 29×29 方板的爱好者，看到一张想做的图，想要一张**能直接照着摆豆、且能按色号备料**的图纸。

判断图纸能否照着拼的标准不是预览图好不好看，而是是否同时具备：**色号图例、行列坐标、每色号用量、透明格留空**。缺任一项，用户拿到手仍拼不出来。

补充约束：用户必须**先选自己实际拥有的品牌/套装与豆径，再生成图纸**。公开资料明确警告「用 291 色生成的图纸，221 色套装填不满」，因此色板选择是生成的前置条件，不是事后切换。

## 1. 决策记录

| 编号 | 决策 | 选择 | 理由 | 被否决方案 |
|---|---|---|---|---|
| D1 | 色号体系 | 多品牌可切换：MARD 221 / MARD 291 / Perler 117 / Hama 89 / Artkal 176 | 色号决定用户能否照着买豆；单品牌会挡住大半用户 | 仅 MARD 221；仅精简自建色板 |
| D2 | 跨品牌等效色 | 用 CIEDE2000 在项目内自算，不抓第三方等效表 | 减少第三方数据依赖；算法与色差模块复用同一套实现 | 直接抓取第三方等效色表 |
| D3 | 色卡数据来源 | 从公开色卡站整理「色号 + 名称 + HEX」成项目内 JSON，标注来源 | 实测可取、无 API Key、数据可版本化 | 用户手工提供色卡；先录精简集 |
| D4 | 首版范围 | 转换+导出、手工编辑、图纸管理三层全要；图纸三种交付形态全要；三类输入图全要 | 用户明确要求 | 分期砍范围 |
| D5 | 转换算法 | 纯浏览器本地、确定性算法，不做 AI 重绘 | 转换是确定性问题，不需要模型；实时预览与离线可用 | 云端 AI 重绘整图 |
| D6 | 照片去背景 | 接入 AI 主体分割，但采用浏览器内 ONNX 模型 | 满足 AI 分割效果，同时保持图片不出浏览器、无 API 成本 | 云端分割 API；纯容差算法（降级用） |
| D7 | 图纸管理 | 账号 + 云同步（本地可运行的后端） | 跨设备继续编辑与拼装进度 | 仅 localStorage |
| D8 | 隐私基线 | 原图不上传、不存储；云端只存网格工程数据 | 降低 D6/D7 引入的隐私与存储成本 | 原图同步到云端 |
| D9 | 部署 | 首版交付可本地运行的完整能力，生产部署不在本次范围 | 部署涉及域名、账号、付费，需单独授权 | 首版即上公网 |

## 2. 范围与实现顺序

范围一次交付，不砍功能；按依赖顺序实现，每阶段可独立验收：

1. 色卡数据 + 网格数据模型（公共契约）
2. 转换链路（上传 → 量化 → 图纸预览 → 参数调节）
3. 手工编辑（改色、擦除、区域换色、撤销重做）
4. 三种交付（PDF 分页、高清 PNG、网页拼装引导）
5. AI 主体分割（可选增强，失败不阻塞主链路）
6. 账号、云同步、图纸管理

## 3. 数据流

```
本地选择/拖拽/粘贴图片
  → ImageBitmap + 离屏 Canvas（图片不上传）
  → [可选] 浏览器内 AI 主体分割 → 透明 PNG
  → 裁剪（锁定/自由比例）+ 缩放到 w×h 格
  → 每格取区域代表色（众数或中位切分，不用平均色，避免边缘发糊）
  → 透明/背景判定为空格
  → Lab + CIEDE2000 最近色匹配所选色板
  → 限色数 + 去孤立点 + 小区域合并（抖动默认关，可调）
  → 色号映射 + 用量统计
  → 渲染：图纸预览 / PDF 分页 / 高清 PNG / 拼装引导
  → 工程数据：本地草稿 +（登录后）云端同步
```

**空值处理**：未上传时显示空态引导，不渲染空网格；全透明图给出「几乎全是背景」提示而非空白图纸；色卡未加载完成禁止生成。

**异常处理**：格式不支持、解码失败、超大图、AI 模型加载失败、色卡缺失、存储配额满、同步失败、登录态过期，各自有明确提示态，不允许白屏或静默出错。

## 4. 状态机与并发

状态：`空态 → 载入中 → 编辑中（参数调节 / 手工编辑）→ 导出中 → 完成 / 错误`

- 互斥：导出中锁定编辑；导出完成或失败后解锁。
- 调参快速连动：每次生成带 `requestId`，只接受最后一次结果，丢弃过期结果。
- 切换色板 / 豆径 / 点「重新生成」会覆盖手工编辑，必须二次确认。
- AI 分割是独立异步任务，失败或取消后回到编辑中，不破坏已有网格。
- 同步与编辑并发：以工程版本号做增量更新，冲突时不静默覆盖。

## 5. 网格数据模型（唯一公共契约）

```ts
type Cell = string | null;              // colorId（色号）或 null（不放豆）
interface Pattern {
  id: string;
  w: number; h: number;                // 格数
  paletteId: string;                   // 套装标识，如 'mard-221'
  beadSize: '5mm' | '2.6mm';
  cells: Cell[];                       // 长度 w*h，行优先
  params: ConvertParams;               // 尺寸、色数上限、抖动、去孤点、抠图开关
  progress: boolean[];                 // 拼装引导已完成标记
  version: number;
  updatedAt: string;
}
```

转换、编辑、三种导出、拼装引导、云同步全部读写这一结构。工程文件即该对象的 JSON 序列化。`cells` 存色号而非 HEX，保证切换色板后仍可追溯、可重新量化。

## 6. 色卡数据

**来源与提取路径**（2026-11-04 实测）：

- `bitbead.app` 品牌列表页 JSON-LD `mainEntity` 为完整 `ItemList`（MARD 221 实测 221 项，含色号与单色页 URL）。
- 单色页 RSC 负载实测含结构化记录：`{"color":{"code":"P81","name":"Light Gray","hex":"#EEE3CF"},"brand":"Perler","size":"md"}`。
- `ipindou.net/colors` 的 JSON-LD 含 839 色 ItemList，但静态 HTML 中未取到结构化 HEX（数据在客户端 chunk），作为备选源，不作为首版依据。
- 抓取脚本需控制请求频率、标注来源与抓取日期，产出纳入版本控制的 JSON；抓取结果人工抽检后再用于生成。

**首版色板**：MARD 221、MARD 291、Perler 117、Hama 89、Artkal 176。Artkal Mini / COCO / DMC 列入后续扩展。

**硬约束**：色卡 HEX 来自公开色卡参考，不是厂商分光光度计实测值，批次染色会偏。因此：

- 图纸**以「色号 + 格内符号」为准**，不依赖屏幕或打印颜色判断颜色；
- 允许用户在编辑阶段手工改色，改色结果以色号记录；
- 界面需明示色值为参考值、实物可能有色差。

**等效色与切换**：跨品牌等效色用 CIEDE2000 在目标色板中找最近色，返回色号与 ΔE；ΔE 超过阈值标记为「近似替代，建议人工确认」。切换色板时**重新跑整体量化**，不做逐格查表替换（逐格替换会累积误差）。另提供「单色替换建议」：查询当前色号在其它品牌中最接近的色号，用于手头缺色时找替代。

**豆径**：5mm 中豆 / 2.6mm 迷你豆由用户显式选择，不按品牌硬编码（公开资料对品牌与豆径的对应关系表述不一致）。29×29 板成品边长参考：5mm 约 14.5cm，2.6mm 约 7.5cm，用于尺寸估算展示。

## 7. AI 主体分割

- 实现：`@imgly/background-removal@1.7.0`（实测存在于 npm），底层 ONNX Runtime Web + ISNet 量化模型，WebGPU → WebGL → WASM 自动降级；模型约 40MB（高质量 fp16 约 80MB），首次使用下载并缓存。
- 触发方式：用户主动点「智能去背景」，默认不执行；下载与推理期间显示进度。
- 输出：透明 PNG 进入第 3 节链路，透明区自动判为空格。
- 失败降级：模型下载失败、设备不支持、内存不足 → 提示并回退到手动擦除，主链路不受影响。
- 隐私：图片始终在浏览器内，不经服务端。
- 模型文件建议自托管或走可访问 CDN，避免首用受境外资源影响。

## 8. 账号与云同步

- 账号：用户名/邮箱 + 密码，服务端存密码哈希，会话用 JWT；无第三方登录、无付费。
- 云端存储内容：`Pattern` 工程数据 + 名称、缩略图、更新时间、拼装进度；**不存原图**。
- 未登录：草稿存 localStorage（同样只存工程数据），可继续完整使用转换与导出。
- 登录后合并：本地草稿上传；同名冲突以更新时间较新者为准，冲突明显时保留两份并提示，不静默覆盖。
- 登录态过期：保留本地只读草稿并明确提示重新登录。
- 后端可本地运行即可满足首版验收；生产部署、域名、第三方服务接入不在本次范围。

## 9. 图纸交付规格

**通用**：每格 = 一颗豆；空格 = 不放豆，在图例中明确说明，不与白色混淆。格内显示底色 + 符号；符号集排除易混字符（0/O、1/I、8/B），用于灰度打印和相近色区分。

**用量表**：色块、色号、名称、颗数、占比（按颗数降序）、总豆数、空格数、所需 29×29 板数、成品尺寸估算。

**A4 打印 PDF**：按 29×29 分板分页，每页含板编号、全局行列坐标（如 R30–R58 / C1–C29）、拼接示意、格内符号、色号图例与用量表；格子边长保证符号可读（目标 ≥6mm）。页数过多时提示并允许分批导出。

**高清 PNG**：单张完整网格图，含坐标、图例、用量表，适配手机/平板放大查看，按屏幕密度单独排版。

**网页拼装引导**：按行或按板高亮当前区段；点击/拖拽标记已完成；显示「已完成 / 需拼总格数」进度；支持只看当前板、只看未完成；进度随 `Pattern` 本地保存与云端同步，刷新后仍在。

## 10. 手工编辑

点格改色、拖拽刷色、橡皮（置为空格）、吸管取色、区域换色（把某色号全部替换为另一色号）、撤销/重做（上限 50 步）。任何编辑即时更新用量表与所有导出视图。

## 11. 边界与失败模式

| 情形 | 表现 |
|---|---|
| 不支持格式 / 损坏文件 | 明确错误态与重选入口 |
| 原图 ≥20MB 或 ≥8000px | 先降采样并提示已降采样 |
| 网格 > 200×200 | 提示分板数过多，要求降低尺寸 |
| 空格占比 > 90% | 提示「几乎全是背景，建议换图或关闭去背景」 |
| 色数超过上限（默认 24） | 自动合并并列出被合并的色号 |
| 色卡加载失败 / 缺失 | 禁止生成并提示，绝不用随机色代替 |
| AI 模型失败 / 设备不支持 | 降级手动擦除，不阻塞主链路 |
| localStorage 配额满 | 提示清理旧草稿，数据不静默丢失 |
| 云同步失败 / 未登录 | 本地草稿保留，显示同步状态 |
| 导出 PDF 页数过多 | 提示并允许分批 |
| 调参快速连动 / 按钮连点 | requestId 丢弃过期结果，导出按钮置禁用 |
| 重新生成覆盖手工编辑 | 二次确认 |

## 12. 架构与模块划分

- **色卡模块**：色板 JSON、色差计算（Lab / CIEDE2000）、最近色与等效色查询。
- **转换模块**：图片解码、裁剪缩放、格子代表色、量化、限色、去孤立点、区域合并、用量统计。
- **分割模块**：浏览器内 AI 去背景、失败降级、透明区处理。
- **图纸模块**：预览渲染、PDF 分页、PNG 导出、符号分配。
- **编辑模块**：手工编辑操作与撤销重做栈。
- **引导模块**：高亮区段、完成标记、进度。
- **存储模块**：本地草稿、工程文件导入导出、登录后的增量同步与冲突处理。
- **服务模块**：账号、会话、工程数据持久化。

依赖方向单向：`色卡 → 转换 → 图纸/编辑/引导 → 存储 → 服务`。所有模块只依赖第 5 节的 `Pattern` 契约。前端构建工具与 UI 框架在实现计划中按用户级《前端开发规范》选定，不改变本节模块边界。

## 13. 备选方案（为何不用更简单的做法）

| 更简单的方案 | 为何不用 |
|---|---|
| 只输出一张彩色网格 PNG，不做色号 | 用户无法照色号买豆，首要目标落空 |
| 自由聚类量化（中位切分） | 色准更好，但产出「买不到的颜色」，与拼豆场景冲突 |
| 逐格查表做跨品牌色号替换 | 累积色差，整体效果劣于重新量化 |
| 云端分割 API | 需上传图片、API Key、付费与隐私设计；浏览器内模型已满足效果 |
| 仅 localStorage 不做账号 | 用户要求跨设备；但本地草稿作为离线降级保留 |
| Floyd–Steinberg 抖动全量开启 | 产生大量孤立单颗豆，实际拼装极其痛苦；默认关、可手动开 |

## 14. 验收标准

1. 用户打开页面 → 拖入卡通图 → 选 MARD 221 / 29×29 → 看到带色号图例、行列坐标、每色号颗数的网格图，且每格颜色都属于 221 色号表。
2. 用户切到 Perler 117 → 颜色、色号、用量表同步重算，近似替代色有明确标记。
3. 用户上传宠物照片 → 点「智能去背景」→ 背景移除、透明区显示为空格；模型下载有进度；失败时可用手动擦除完成。
4. 用户导出 PDF → 得到按 29×29 分页、带全局行列坐标、色表与每色号颗数的 A4 文件；导出 PNG 得到高清整图；进入拼装引导可逐行高亮、点格标记完成，刷新后进度仍在。
5. 用户在 A 设备登录保存图纸 → B 设备登录后看到同一图纸与拼装进度；未登录时的本地草稿在登录后不丢失。

## 15. 测试策略

- 单元：CIEDE2000 已知色对、最近色匹配、限色与去孤立点、分板切分与坐标、用量统计、等效色 ΔE、工程文件序列化与版本冲突。
- 视觉回归：卡通、像素画、宠物照片、透明 PNG 四类基准图生成图纸快照对比，防止算法改动引入整体偏色。
- 端到端：上传 → 调参 → 手工编辑 → 三种导出 → 拼装引导 → 登录同步。
- 边界：超大图、全透明图、单色图、损坏文件、模型加载失败、存储配额满、登录态过期。
- 色卡数据：抓取结果抽检色号与 HEX 一一对应、无重复、无空值。

## 16. 明确不在本次范围

生产部署与域名、第三方登录、付费与配额、社区图纸库与分享、移动端原生 App、自定义色卡录入界面（首版色卡由脚本整理）、多人实时协作、AI 整图重绘。

## 18. 保持原图比例与显式生成（2026-11-05 追加）

> 本章为需求文档冻结后的追加需求，仅记录「为什么」；现状描述见 `docs/功能规格/拼豆图纸生成器.md`。

### 用户场景

用户上传一张长宽比 1:2 的图片，希望图纸保持这个比例，而不是一律按默认 29×29 生成；并且不希望上传成功就自动出图，要先看清检测到的比例与推荐尺寸、确认参数，再手动点「生成图纸」。

### 决策记录

| 决策 | 选择 | 理由 | 被否决方案 |
|---|---|---|---|
| 尺寸基准 | 以默认 29×29 的总格数（841 格）为基准，按图片比例分配宽高 | 成品大小与用豆量和原有默认体验一致，长图不会突然翻倍 | 固定短边 29（1:2 会变 29×58 = 1682 格）；固定长边 29（短边被压得过小） |
| 比例精度 | 以宽为基准推高，用精确比例 | 推荐值与「锁定比例」输入联动公式一致，避免推荐 21×41、联动却算出 21×42 的困惑 | 先算高再算宽（两次 round 产生比例偏差） |
| 生成时机 | 上传只解析并进入待生成态，必须点「生成图纸」；**首次生成之后**参数/源图变化仍实时重算 | 满足「上传 ≠ 生成」，同时保留出图后的实时调参体验；也避免 200×200 每次拖滑块都重算 | 所有改动一律手动生成（AI 抠图后看不到效果、回退无从对比，体验倒退） |
| 比例锁定 | 默认开启，用户可关闭 | 改宽或高时自动保持原图比例；需要 200×200 这类自由尺寸时一键关闭 | 只给推荐值、不做联动（用户手调宽高会破坏比例） |

### 验收标准

1. 用户上传 1:2 图片 → 不出现图纸，看到「原图已就绪」卡片、检测到的比例与推荐尺寸（21×42）
2. 用户改宽为 40 → 高自动变 80；关闭锁定后再改宽，高不再变化
3. 用户点「生成图纸」→ 得到 21×42 的图纸，按钮变为「重新生成」
4. 生成之后，智能去背景、恢复原图、重新生成仍能正常工作
5. 用户再上传一张 2:1 图片 → 清空旧图纸、回到待生成、推荐 41×21

## 19. 按色号高亮（2026-11-05 追加）

> 本章为需求文档冻结后的追加需求，仅记录「为什么」；状态：已实现（2026-11-05）。实现现状见 `docs/功能规格/拼豆图纸生成器.md`。

### 用户场景

用户在拼装阶段想一次只拼一种颜色：选一个色号，图纸上只有这个色号保持醒目，其它颜色不再干扰；拼完再选下一个色号，直到全部拼完。

### 决策记录

| 决策 | 选择 | 理由 | 被否决方案 |
|---|---|---|---|
| 非选中色的表现 | 在 `drawCells` 把底色混向纸色到 12% 浓度，`drawLabels` 跳过其色号；坐标、格间虚线、5×5 粗线全部保留 | 保留构图与定位能力，同时消除其它颜色的干扰；不引入新线型、不遮挡任何既有绘制层 | 整格半透明蒙层（会盖住虚线和色号，违反绘制层次）；canvas CSS filter（截图与导出表现不一致）；完全留白（与「空格 = 不放豆」混淆） |
| 作用位置 | 工作台「备豆清单」+ 拼装引导页色号条 | 工作台已有按颗数排序的色号清单，引导页才是「一种一种颜色去拼」的主战场 | 只做工作台（真正拼的时候用不上）；只做引导页（备豆阶段无法核对） |
| 导出是否跟随 | **不跟随**，PNG / PDF 始终是完整全彩图纸 | 导出是打印交付件，一次只印一种颜色会迫使用户打 N 份；且交付标准要求预览 / PNG / PDF 三处色号一致。高亮定位为屏幕拼装辅助 | 跟随高亮按色分图导出（需改 `png.ts` 与独立实现的 `pdf.ts`，实质是「分色图纸」另一个功能，单独排期） |
| 状态归属 | `App.tsx` 的纯 UI state `highlightCode: string \| null` | 工作台与引导页共享选中态；不写进 `Pattern`，避免牵动序列化、服务端校验与云同步契约 | 写入 `Pattern`（污染唯一公共契约）；各页面各自持有（切换视图即丢失） |
| 与既有状态共存 | 与逐行红框、已完成深色覆盖、画笔色号 `activeCode` 相互独立 | 点色号不该误改画笔；逐行定位与按色过滤解决的是两个不同问题 | 复用 `activeCode`（点备豆清单会意外改变画笔颜色） |

> 注：本章描述的「逐行红框」已在 §20 改为按 29×29 板定位，此处保留当时的决策语境。

### 边界与失败

- 空格（不放豆）在任何时候都保持浅底 + 小圆点，不参与淡化，不与「被淡化的豆」混淆。
- 换色板、重新生成、导入或打开另一张图纸后，若选中色号已不在 `cells` 中，自动清除高亮回到全彩，不出现「选了颜色但整张图都淡掉」的死状态。
- 高亮态下其它色号不画色号文字、不画已完成深色覆盖；选中色号照常显示色号与进度，避免深灰块反而成为新的干扰源。
- 200×200 网格只增加一次逐格判断，不新增绘制 pass。
- 全透明图纸没有可高亮色号，色号条只显示「全部」。

### 验收标准

1. 用户打开一张图纸 → 在备豆清单点某个色号行 → 该行呈选中态，图纸上只有这个色号保持原色与色号，其余格子淡到几乎无色但仍能看出位置；坐标、5×5 粗线、格间虚线、空格圆点仍清晰。
2. 用户再点同一行 → 取消高亮，图纸恢复全彩。
3. 用户点「开始拼」→ 在色号条选一个色号 → 图纸只高亮该色并显示该色剩余颗数；点格子标记完成后剩余数减 1；可继续逐个切换色号。
4. 用户在高亮态下切色板或重新生成 → 若色号失效，高亮自动清除，不留下全淡图纸。
5. 用户在高亮态下导出 PNG 和 PDF → 得到的文件与未高亮时完全一致（完整全彩、每格都有色号），控制台零错误。

## 20. 引导页改按色为主、交付补齐（2026-11-05 追加）

> 本章为需求文档冻结后的追加需求，仅记录「为什么」；状态：已实现（2026-11-05）。实现现状见 `docs/功能规格/拼豆图纸生成器.md`。

### 用户场景

用户实际拼豆是「拿一袋同色号的豆，把图纸上这个色号的位置全部填满，再换下一袋」，不会一行一行地换色拼。但引导页把逐行推进做成主流程（上一行/下一行、第 N/M 行、整行红框），主次颠倒。用户在大图上仍需要一个空间定位单位，合适的是 29×29 拼豆板。此外，需求 §9/§10/§15 中「按板高亮 / 只看当前板 / 只看未完成」「区域换色」「分批导出」「渲染与导出自动化」一直未落地。

### 决策记录

| 决策 | 选择 | 理由 | 被否决方案 |
|---|---|---|---|
| 逐行功能 | **移除逐行主流程**（上一行/下一行、整行红框、隐藏已完成行），改为按板定位 | 与按色拼互斥，放在同页会误导用户先按行推进；红框机制保留但改为板框 | 保留逐行作为可选开关（两套顺序并存更混乱）；彻底删掉所有定位辅助（大图无参照） |
| 定位单位 | 29×29 拼豆板：上一板/下一板 + 当前板红框 + 「只看当前板」淡化板外 | 一次摆一块板，正好是 PDF 分板与实物板的单位；顺带补上需求 §9 未实现的按板能力 | 继续用行；用 5×5 大块（太碎，一块板要切 36 次） |
| 只看未完成 | 从「隐藏已完成行」改为全局「隐藏已完成格」（已完成格淡化、不写色号） | 按色拼时完成是逐格发生的，行级判断没有意义 | 按行判断 |
| 渲染层自动化 | Vitest + 记录型 Canvas 2D mock 断言绘制调用；把 PNG 画布布局、板范围钳制、区域换色抽成纯函数 | 项目已有 Vitest，零新依赖、不破坏 N150 零编译部署；能覆盖「哪格填什么色 / 写什么字 / 线画在哪 / 内容是否落在画布内」 | 引入 node-canvas（原生编译，破坏部署）；把 Playwright 加进 devDependencies（下载浏览器、影响部署）；只靠人工截图（已导致三轮返工） |
| 区域换色 | 选中色号后从色板挑目标色，一次性替换该色号的全部格子，进撤销栈 | 补上需求 §10；与按色高亮的选中态天然衔接 | 增加第四种画笔工具（只能逐格刷，不是「区域」换色） |
| PDF 分批 | 板数 > 12 时提示，允许输入起止板号只导出该段；主按钮仍导出全部 | 需求 §9「页数过多时提示并允许分批导出」；大图一次几十页不方便打印 | 静默一次导出全部；自动拆成多个文件（用户无法选范围） |
| 色板扩展 | 只加 **Artkal Mini 221** 与 **COCO 291**（同源 RSC 三元组、页面声明色数与提取数一致、实测原有 5 套数据逐字节未变）；**不加 DMC** | 前两套是可直接买到的拼豆套装；DMC 页面实测返回 200 但内容是「绣线色号 ↔ 近似豆号」HTML 对照表，色号买不到对应的豆，字段也不是 `code/name/hex` | 为凑数把 DMC 当成拼豆色板（会让用户按绣线线号买豆）；编造 HEX |
| 导出与交互态 | 维持 §19 决策：高亮、板定位、隐藏已完成一律不进入 PNG / PDF | 导出是打印交付件 | — |

### 边界与失败

- 区域换色：源色不在图纸中 / 目标色等于源色 → 不改动、不产生撤销记录；替换后用量表、替代建议、导出立即重算；撕掉色板后目标色失效可重新选。
- 板范围：非法输入（非数字、倒序、越界）一律钳制到 `[1, 板数]`，不生成空 PDF；分批导出的页眉仍用**全局**板号。
- 板定位：单板图纸不显示板切换；按板淡化与按色高亮叠加时，两者都表示「暂时不关注」，被抑制的格子不能在中心留下文字或深色进度块。
- 隐藏已完成：空格永不标记完成；已完成格子的坐标与 5×5 线仍保留。

### 验收标准

1. 用户进「开始拼」→ 看不到上一行/下一行 → 看到按色号的主色条与「板 1/N」切换；点某色号，图纸只高亮该色并显示剩余颗数。
2. 用户开「只看当前板」→ 板外格子淡化、当前板有红框；切到下一板，红框与淡化区域一起移动。
3. 用户开「隐藏已完成」→ 点过的格子淡化，进度数字仍正确，刷新后进度仍在。
4. 用户在备豆清单选一个色号 → 点「区域换色」→ 挑目标色并确认 → 该色号所有格子变成目标色、用量表合并、撤销一次可回到替换前。
5. 用户打开 60×60 图纸（9 块板）→ 导出区提示可分批 → 输入 2–4 并导出 → 得到 3 页 PDF，页眉仍是全局 `BOARD 2/9 … 4/9`。
6. `npm test` 覆盖渲染层绘制调用与上述纯函数；浏览器验收仍按交付标准做截图 + 2 倍放大 + PDF 冒烟；导出的 PNG / PDF 不受任何交互态影响。

## 20. 图纸市集与图纸仓库（2026-11-06 追加）

> 本节只记录边界变更；完整设计见 `docs/requirements/图纸市集与图纸仓库.md`（已实现、已冻结）。
