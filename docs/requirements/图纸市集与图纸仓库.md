# 图纸市集与图纸仓库 · 需求文档

> 状态：已实现（2026-11-06）
> 实现现状见：docs/功能规格/拼豆图纸生成器.md
> 讨论日期：2026-11-05 ~ 2026-11-06
> 文档职责：回答「为什么这么做」——场景、范围、方案对比、决策记录、验收标准。本文件已冻结，仅在有追加需求时新增章节。

## 0. 一句话场景与范围

一个用「微豆」做拼豆图纸的用户，想把自己仓库里的某张图纸发布出去让别的账号看到、搜索到、另存回去；同时自己的私人图纸要有预览图和名字，图纸多了也能快速找出来。

本次范围：
1. 产品中文名由「豆格」改为「微豆」（项目代号 WeDou 不变）。
2. 「图纸库」改名为「图纸仓库」，只展示当前账号（或本地浏览器）自己的图纸，改成带预览图的卡片网格，支持按名称搜索、重命名。
3. 新增「图纸市集」：用户从自己的仓库选择图纸发布，市集条目公开、所有访客可见可搜索；作者可撤销；其他登录用户可把市集图纸另存为自己的独立副本。
4. 两处都按图纸名称搜索；名称是发布的必填项。

明确不做：评论、点赞、收藏、关注、举报、作者主页、标签分类、审核后台、举报下架、跨设备实时通知、私信、图纸版本历史。

## 1. 决策记录

| 编号 | 决策 | 选择 | 理由 | 被否决方案 |
|---|---|---|---|---|
| D1 | 产品名 | 中文名「微豆」，代号 WeDou 不变 | 与仓库/域名/服务名一致 | 保留「豆格」 |
| D2 | 私人仓库可见范围 | 仅本人：登录后按 `user_id` 取云端，未登录只取本地 `localStorage` 草稿 | 用户原话「一个用户只能看到自己的图纸仓库」 | 展示他人已发布内容到私人仓库 |
| D3 | 市集可见范围 | 免登录只读（列表、搜索、详情）；发布、撤销、另存需登录 | 「公开的，所有人可见」 | 市集也要求登录 |
| D4 | 静态版 | `VITE_STATIC_MODE=1` 或后端不可用时隐藏市集入口、禁用分享并提示「本地模式」 | GitHub Pages 无后端，无法提供公开数据 | 构建期生成只读快照（无法实时反映新发布，需改 CI） |
| D5 | 发布的数据形态 | 发布时复制一份**独立快照**到 `market_items`，含完整 `cells/params` 与缩略图；原图纸后续改名/编辑/删除不影响市集 | 社区发布语义，避免引用悬空和原图纸被删导致市集 404 | 引用原 `patterns` 行（原图删除即消失、改动会实时串改市集） |
| D6 | 重复发布 | `(owner_id, source_id)` 唯一；再次发布更新同一条市集记录（保留条目 id、刷新名称/快照/缩略图） | 一张私人图纸只对应一个市集条目，链接不失效 | 每次发布新增一条（会产生重复刷屏） |
| D7 | 市集图纸的可用动作 | 登录用户可「保存到我的图纸仓库」，生成新 id、`version=1` 的独立副本 | 社区的实际价值在于能拿走继续用；用户确认按推荐方案执行 | 只读浏览；只导出 PNG/PDF 不入库 |
| D8 | 命名 | 发布时名称必填且不得为默认「未命名图纸」（1–80 字符）；仓库卡片提供重命名，改名同步本地草稿与云端 | 默认名对搜索毫无意义；用户确认按推荐方案执行 | 发布时另填市集别名；完全不强制 |
| D9 | 搜索 | 仓库前端按名称过滤（数据已全在内存）；市集后端按名称 + 作者名 `LIKE` 过滤并分页 | 仓库数据量小，市集需要避免把全部 `cells` 拉到浏览器 | 市集也拉全量前端过滤（传输过大） |
| D10 | 缩略图 | 浏览器按 `cells` 降采样画纯色块小 canvas → PNG dataURL；仓库实时生成，市集在发布时生成一份存 `thumb` 字段 | 服务端是纯 Node + `sql.js`，没有 Canvas/图形库，项目基线是零编译依赖、原图不上传 | 服务端生成 PNG（要引入原生图形依赖）；列表返回完整 `cells` 再前端画（传输大、慢） |
| D11 | 缩略图与交付件的关系 | 缩略图是**预览**，纯色块、不写色号、不画 5×5 分块线 | 格子小于 `MIN_CODE_CELL` 时按交付标准应留白；预览不是给用户照着拼的操作件 | 复用 `renderPatternPng`（32px/格、含图例，列表批量会卡） |
| D12 | 数据库写入成本 | 只在发布/撤销时写 `market_items`；浏览走只读查询；列表不 SELECT `cells/params` | `sql.js` 每次写都整库 `export()` + rename，写放大会拖慢所有保存操作 | 浏览量计数、点赞等高频写 |
| D13 | 隐私 | 市集只含图纸网格工程数据、名称、作者名、缩略图；绝不含原图、密码哈希、恢复码、拼装进度 | 沿用 D8 隐私基线；作者用户名是发布内容的必要署名 | 公开整个 `Pattern`（含 `progress`） |
| D14 | 既有「不做社区」边界 | 在 `docs/requirements/拼豆图纸生成器.md` 追加章节显式改边界，不改写已冻结的原文 | 双轨制：冻结文档只追加 | 直接改写历史决策行 |

## 2. 数据流

- **仓库**：`localStorage['wedou.drafts']` + 登录时 `GET /api/patterns` → `mergedLibrary()` 按 id 取较新者 → 前端按名称过滤 → 卡片渲染（预览图由 `renderThumbDataUrl(pattern)` 实时生成）。
- **重命名**：卡片输入 → `touch()` 抬 version/updating → `upsertDraft` → 登录时 `POST /api/patterns`（现有 upsert 接口即可，无需新路由）→ 刷新云列表。
- **发布**：卡片「分享到市集」→ 校验名称 → `renderThumbDataUrl` → `POST /api/market { pattern, thumb }` → 服务端校验名称/网格/缩略图 → 查 `(owner_id, source_id)` 决定 INSERT 或 UPDATE → 返回条目摘要 → 刷新 `sharedIds`。
- **市集列表**：`GET /api/market?q=&limit=&offset=` → 免登录；`SELECT` 只取摘要列（不含 `cells/params`）→ 参数化 `LIKE` 搜索名称/作者 → 按发布时间倒序分页；若请求带有效会话，额外返回该用户已发布的 `source_id` 数组。
- **市集详情/另存**：`GET /api/market/:id`（免登录，含完整 `cells`）→ 登录用户点「保存到我的图纸仓库」→ `createPattern()` 生成新 id 与全新 `progress` → `upsertDraft` + `POST /api/patterns` → 切到图纸仓库。
- **撤销**：作者在自己的条目上点「撤销分享」→ `DELETE /api/market/:id`（服务端校验 `owner_id`）→ 刷新市集与 `sharedIds`。
- **空值**：无图纸 → 仓库空态「还没有保存的图纸」；市集为空 → 空态「市集还没有图纸」；搜索无结果 → 「没有匹配的图纸」并保留清空搜索的入口。
- **异常**：网络/后端不可用 → 市集显示错误提示 + 重试按钮，不白屏；静态版/后端不可用 → 隐藏市集入口、仓库分享按钮给出「本地模式」提示；发布失败（未命名、未登录、400/401/500）→ toast 说明原因，不改动本地数据。

## 3. 状态机

- 仓库卡片：`未分享 → 已分享 → 未分享`（发布 / 撤销）；`已分享` 再次发布 = 更新快照，状态不变。
- 市集视图：`加载中 → 正常 / 空 / 无搜索结果 / 错误`；错误态出口是「重试」。
- 详情弹窗：`关闭 → 打开 → 另存中 → 另存成功（回仓库）` 或 `另存失败（回到弹窗并提示）`。
- 互斥：同一张图纸的「发布」与「撤销」按最新一次服务端结果为准；快速双击由按钮在请求期间禁用，避免并发写产生两条记录（数据库唯一键是最后兜底）。
- 登录态切换：登出后清空市集的 `sharedIds`、关闭详情弹窗；登录后重新拉取市集列表与自己的分享状态。

## 5. 边界与失败

| 情形 | 行为 |
|---|---|
| 未登录 / 静态版 | 仓库仍可用；市集入口在静态版隐藏；非静态但未登录时市集可浏览，分享/另存提示登录 |
| 分享「未命名图纸」 | 前端直接拦截并提示先重命名；服务端二次校验返回 400，不落库 |
| 名称超长 / 只含空格 / 含控制字符 | trim 后长度 1–80，否则 400；前端输入框限制 `maxLength` |
| 搜索词含 `%` `_` `\` | 后端去掉 SQL 通配符再参数化 `LIKE`，避免意外全表匹配 |
| 搜索词超长 | 截断到 80 字符 |
| 超大图纸（200×200 = 40000 格） | 缩略图降采样到最长边 200px，dataURL 上限 200KB；列表不返回 `cells` |
| 缩略图缺失 / 非法 dataURL | 服务端 400；已有条目显示占位块，不破图 |
| 分页越界 | `limit` clamp 1–60、`offset` clamp ≥0，返回空数组而非报错 |
| 撤销他人的条目 / 不存在的 id | 403 / 404，不删数据 |
| 原图纸改名为空、被删除、被覆盖 | 市集快照不受影响；作者仍可在市集撤销 |
| 匿名访客打开市集 | 列表/详情可读，`sharedIds` 为空，不显示任何写操作 |
| 后端 500 / 断网 | 市集错误态 + 重试；仓库照常从本地草稿工作，控制台不抛未捕获异常 |
| 多标签页同时发布同一图纸 | 数据库 `(owner_id, source_id)` 唯一键兜底，后写覆盖同一条 |
| 市集条目很多 | 默认每页 24 条，后端分页；不做无限滚动 |

## 6. 方案对比

| 方案 | 做法 | 优点 | 不选的原因 / 取舍 |
|---|---|---|---|
| A 市集引用原 `patterns` 行 + 加 `is_public` 字段 | 最小改动，一条 SQL 就能公开 | 表结构改动少 | 原图纸删除/改名会直接串改市集；公开表与私表混在一起，`requireUser` 边界容易漏；备份与隐私边界模糊 |
| **B 独立 `market_items` 快照表 + 免登录只读 API（选中）** | 发布时复制网格与缩略图，写接口鉴权、读接口公开 | 私有与公开彻底隔离；原图删除不影响市集；列表不传 `cells`；旧数据零迁移 | 多一张表、5 个路由、一份冗余 cells |
| C 接第三方社区/对象存储服务 | 现成社区能力 | 功能多 | 违反「零 Secrets、不登录也能用、图片不上传」基线，引入付费与运维 |
| D 服务端生成缩略图 PNG 存文件 | 列表直接给 URL | 前端零计算 | Node 无 Canvas、需原生图形依赖，破坏零编译部署；文件还要过 `rsync --delete`/备份 |
| **E 浏览器降采样生成 dataURL（选中）** | 仓库实时画、市集发布时存一份 | 零依赖、零上传原图、传输小、与交付标准的「格子小不写字」一致 | 依赖浏览器 Canvas；静态环境不能生成（静态版本来就不发布） |

选 B + E：付出「一张表 + 一份快照 + 一个缩略图模块」，换来私有/公开数据隔离、原图与隐私基线不被破坏、列表性能可控。

## 7. 验收标准

1. 用户打开页面 → 顶栏品牌显示「微豆」，导航为「工作台 / 开始拼 / 图纸仓库 / 图纸市集」→ 点「图纸仓库」看到自己保存的图纸以带预览图的卡片展示，输入名字片段能立刻筛出对应卡片。
2. 用户 A 登录 → 把一张叫「小熊」的图纸改名并点「分享到市集」→ 图纸仓库该卡片显示已分享；尝试分享一张「未命名图纸」被提示先命名，市集不会出现它。
3. 用户 B 用另一个账号登录 → 打开「图纸市集」搜索「小熊」→ 看到 A 发布的图纸卡片（有预览图、名称、作者名）→ 点「保存到我的图纸仓库」→ 切到仓库能看到独立副本，且 A 之后撤销分享，B 的副本仍在。
4. 未登录访客打开「图纸市集」→ 能看到并搜索已发布图纸，但看不到「分享/撤销/另存」的可用入口或点击后提示登录；A 撤销后刷新，该图纸从市集消失。
5. 用户用静态版（本地模式）打开 → 看不到市集入口，仓库仍可用且分享按钮给出本地模式说明；全程控制台零产品错误，桌面与手机宽度下卡片不溢出。

## 8. 与既有决策的冲突处理

- `README.md` 与 `docs/requirements/拼豆图纸生成器.md` 原文写过「不含社区图纸库」「社区图纸库与分享不做」。本次是用户明确提出的新需求，按 D14 在冻结文档追加章节显式改边界，并在活文档/README 里改成现状描述。
- `docs/requirements/拼豆图纸生成器.md` 曾预留「云端存储内容含缩略图」但从未实现；本次只在市集表落 `thumb`，私表 `patterns` 仍不存缩略图（仓库预览实时生成），避免旧数据迁移。
- 品牌改名只改用户可见中文名；`package.json` 的 `wedou`、服务日志 `WeDou`、PDF 页脚 `WeDou`、cookie/存储键前缀均保持不变。
