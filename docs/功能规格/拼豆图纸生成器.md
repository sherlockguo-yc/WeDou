# 拼豆图纸生成器 · 功能规格

> 活文档：描述「现在怎么工作」。修改功能前必读；实现变化必须跟随更新。
> 决策历史见 `docs/requirements/拼豆图纸生成器.md`（已冻结）。

## 1. 现状概览

单页 React 应用 + 本地 Express 后端。前端完成图片解码、网格采样、颜色量化、优化、图纸渲染与全部导出；后端只做账号认证与 `Pattern` 工程数据持久化。图片从不离开浏览器。

- 开发：Vite 5173，`/api` 代理到 Express 3001
- 生产：`npm run build` 后 `npm start`，Express 同时托管 `dist/` 与 `/api`

## 2. 数据流

```
File / 拖拽 / 粘贴
 → createImageBitmap → Canvas → ImageData（>4000px 降采样）
 → 分析宽高比 → recommendGridSize 推荐网格（保持比例、约 841 格）→ 进入 pending 态，**不转换**
 → 用户点「生成图纸」→ generated = true
 → [可选] 浏览器内 ISNet 去背景 → 透明 ImageData（已生成态会自动重算）
 → sampleCells：透明在像素层判定；背景是格子级判定（四角同色 + 从画面边缘连通漫延，默认关闭）
 → quantizeImage（唯一入口，按 dithering 选分支）
   · 默认 quantizeByVote：每个抽样像素先映射到真实色号 → 按色号投票定该格；被多数票淹没、但连成线的强对比细节可覆盖主色（默认开，可关）
   · 抖动 sampleGrid + quantizeGrid：每格取直方图众数代表色 → CIEDE2000 最近色 + Floyd–Steinberg 误差扩散
 → optimizeGrid：limitColors → mergeSmallRegions → removeIsolated
 → createPattern → React state
 → drawGrid（Canvas 预览，可带纯 UI 的 highlightCode）/ renderPatternPng / exportPatternPdf / GuideView
 → localStorage 草稿；登录后 POST /api/patterns
```

转换在 `App.tsx` 的 `useEffect` 中执行，**前置条件是 `source && generated`**；用 `requestRef` 递增的 requestId 丢弃过期结果，40ms 延时让 loading 态先渲染。上传只做解码、比例分析和推荐尺寸，并置 `generated=false` / `pattern=null`，所以不会出图。首次点「生成图纸」后 `generated=true`，此后参数、色板、豆径、源图变化仍自动重算（保留实时预览），有手工修改时先弹确认。「重新生成」是同一按钮在已生成态的文案，走 `regenerate()` 强制重算。UI 只调用 `quantizeImage`，不感知内部分支。

**按色号高亮是纯展示分支**：`highlightCode` 只从工作台备豆清单或引导页色号条流入 `GridOptions`，不参与量化、不写入 `Pattern`、不传给 PNG / PDF。

## 3. 公共契约 `Pattern`

`src/core/types.ts`。`cells: (string|null)[]` 存**色号**而非 HEX，长度恒为 `w*h`，行优先；`null` = 不放豆。`progress: boolean[]` 与 `cells` 等长。`version` 每次修改自增，`updatedAt` 为 ISO 字符串。

工程文件即该对象的 JSON（`core/pattern.ts` 的 `serialize` / `parsePattern`，导入时校验长度与格子类型）。

## 4. 模块与文件

| 模块 | 文件 | 职责 |
|---|---|---|
| 色差 | `src/core/color.ts` | sRGB→Lab、CIEDE2000、最近色、跨品牌等效色 |
| 色板 | `src/core/palettes.ts` | 加载 `palettes.json`、色号索引、Lab 缓存 |
| 采样/量化 | `src/core/convert.ts` | `sampleCells` 统一格内像素定义、按色号投票、抖动路径、桶→色号缓存、统一入口 `quantizeImage` |
| 优化 | `src/core/optimize.ts` | 限色、小区域合并、去孤立豆 |
| 分板/比例 | `src/core/boards.ts` | 29×29 分页与全局坐标、`recommendGridSize` 按原图比例推荐网格、分批导出的 `clampBoardRange` |
| 统计 | `src/core/stats.ts` | 用量表、板数、成品尺寸 |
| 工程模型 | `src/core/pattern.ts` | 创建、序列化、校验、冲突判定、`replaceCode` 区域换色 |
| 开关偏好 | `src/core/preferences.ts` | 7 个开关的布尔快照、字段级校验、localStorage 读写及与 `DEFAULT_PARAMS` 合并 |
| AI 分割 | `src/core/segment.ts` | CDN 动态 import、进度、120s 超时、失败降级 |
| 渲染 | `src/render/grid.ts`, `png.ts`, `pdf.ts` | Canvas 网格（`isSuppressed` 统一抑制判定）、PNG 整图（`pngLayout` 纯几何）、A4 分页 PDF（支持板范围切片） |
| 界面 | `src/views/*.tsx`, `src/components/*.tsx` | 工作台、引导、图纸仓库、图纸市集、登录、控件 |
| 图纸视口 | `src/components/ChartViewport.tsx` | **默认适应窗口**（`fit=true`）、缩放档位 `[8,12,16,22,30,42]`、全屏（Esc 退出），工作台与拼装引导共用 |
| 缩略图 | `src/render/thumbnail.ts`, `src/components/PatternThumb.tsx` | 按色号降采样纯色块、PNG dataURL 与缓存；仓库实时生成、市集用已存 dataURL |
| 图纸仓库 / 市集 | `src/views/LibraryView.tsx`, `MarketView.tsx` | 私人卡片网格与搜索/改名/分享；公开列表、搜索、详情与另存 |
| API | `src/api/client.ts`, `server/*.mjs` | fetch 封装、认证、私有图纸 CRUD、公开市集、静态托管 |

**默认全图预览**：`ChartViewport` 的 `fit` 初值为 `true`，`.canvas-scroll.is-fit .chart-canvas` 用 `max-width/max-height: 100%` + `width/height: auto` 把 canvas 等比缩到容器内（宽图与竖图都不出现滚动条），缩小时用 `image-rendering: auto` 保持平滑。点「放大」退出 fit 并升一档 `cell` 回到原生尺寸，点「适应窗口」回到全图；fit 时「缩小」按钮禁用，避免出现「点缩小反而只剩局部」。CSS 只改显示尺寸，`cellFromPoint` 用 `getBoundingClientRect()` 与 canvas 原生尺寸的比例换算，点格改色/标记完成不受影响。

**按色号高亮链路**：`App.tsx` 的 `highlightCode` → `StudioView` / `GuideView` → `ChartViewport` → `ChartCanvas` → `grid.ts` 的 `GridOptions.highlightCode`。色号清单来自 `usageRows(pattern)`（只列图纸实际用到的色号）。`grid.ts` 导出纯函数 `isDimmed` / `dimmedFill` / `isSuppressed`，单测在 `tests/grid.test.ts` 与 `tests/render.test.ts`（后者用记录型 Canvas 2D mock 覆盖绘制调用、线型、抑制规则与导出布局）。

## 5. 后端 API

认证：scrypt 密码哈希（每次重置换盐）+ HMAC-SHA256 JWT（httpOnly cookie `wedou_session`，30 天）。密钥首次启动时生成并存于 `server/data/secret`。

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/auth/register` | 用户名 2–32 位、密码 ≥6 位；重名返回 400。返回 `{user, recoveryCode}` |
| POST | `/api/auth/login` | 校验后写 cookie |
| POST | `/api/auth/reset` | 凭用户名 + 一次性恢复码 + 新密码重置；成功后**旧码作废并返回新码**，自动写入会话 |
| POST | `/api/auth/logout` | 清 cookie |
| GET | `/api/auth/me` | 返回当前用户或 `null` |
| GET | `/api/health` | 返回 `storage: sqlite`、DB 路径与备份目录 |
| GET | `/api/patterns` | 未登录 401 |
| POST | `/api/patterns` | upsert；校验 `w/h ≤ 300` 与 `cells.length === w*h`；云端版本更新时返回 409 并带云端对象 |
| DELETE | `/api/patterns/:id` | 删除 |
| GET | `/api/market` | **免登录**；`q` 按名称/作者做 `instr` 字面子串匹配（不解释 `%`/`_`），`limit` 钳制 1–60、`offset` ≥0；只返回摘要（不含 `cells/params`），带登录者自己的 `shared`（`{id, sourceId}[]`）映射 |
| GET | `/api/market/:id` | **免登录**；返回含完整 `cells/params` 的详情，不存在 404 |
| POST | `/api/market` | 需登录；校验网格、名称（trim 后 1–80 字且非「未命名图纸」）、PNG dataURL 缩略图（≤200KB）；按 `(owner_id, source_id)` 唯一键 upsert，重复发布更新同一条 |
| DELETE | `/api/market/:id` | 需登录且必须是作者，否则 403；不存在 404 |

**存储：`sql.js`（WASM SQLite）**，`server/store.mjs`。选它是因为 N150 运行在 Node 20（无 `node:sqlite`、无 nvm），引入原生模块会破坏「零编译、零 Secrets」的部署链路。`server/data/wedou.sqlite` 内有 `users`（id / username / password_hash / salt / recovery_hash / created_at）、`patterns`（复合主键 `user_id + id`，cells/params/progress 存 JSON，带 `user_id + updated_at` 索引）与 `market_items`（`id` 主键、`(owner_id, source_id)` 唯一、作者名/名称/尺寸/色板/完整 cells/params/缩略图/发布时间，带 `created_at` 索引）。市集是**发布时的独立快照**：原图纸改名、编辑或删除都不影响它，作者可撤销。列表查询不 SELECT `cells/params`，且只在发布/撤销时写库，避免 `sql.js` 每次写整库 `export()` 带来的放大。每次写用 `写临时文件 + rename` 原子替换，并每 6 小时自动快照到 `server/data/backups/`（保留最近 10 份）。`WEDOU_DATA_DIR` 可覆盖数据目录用于测试。

**公开数据边界**：市集只含网格工程数据、名称、作者用户名与浏览器生成的预览图，不含原图、拼装进度、密码哈希或恢复码；读接口用 `userFromRequest` 的可选登录态，写接口一律 `requireUser`。

**备份范围决策（2026-11-05）**：明确**只保留本机快照，不做异地备份、不接额外副本或告警服务**。自用与少数朋友的场景下，现有 6 小时快照已足够；此项不再列为待办或风险。

服务启动时 `await initDb()` 建表，并一次性把旧 `users.json` / `patterns/*.json` 导入 SQLite，原文件重命名为 `.migrated` 保留回滚余地（已实测用户、图纸、版本、cells 无损）。

> 运维注意：`sql.js` 是**进程内**数据库。所有读写必须经服务进程；直接修改 `wedou.sqlite` 文件不会同步到运行中的实例，且该实例下一次写会用内存状态覆盖外部修改。需要修正数据时，改完文件后必须让服务重新加载（走 CI → webhook 自动部署，不手动重启）。**恢复码**是 16 字符随机串，服务端只存 SHA-256 哈希、用 `timingSafeEqual` 比对，注册或重置成功后只展示一次；用它替代邮件找回，避免引入 SMTP 凭据、付费服务或用户隐私外传。

## 6. 状态与边界

状态：`empty → pending → loading → ready/exporting → error`。`pending` 由上传进入（`source` 已就绪、`generated=false`、`pattern=null`），显示待生成卡片（比例、推荐尺寸、原图预览、生成按钮）；只有点「生成图纸」才进入 `loading`。导出中禁用编辑按钮；切色板/改参数/点重新生成在 `dirty` 时弹二次确认；AI 分割是独立任务，失败只提示不破坏已有网格。

**按色号高亮（纯 UI 态）**：`highlightCode: string | null` 存在 `App.tsx`，工作台与引导页共享，默认 `null`（全彩）。点备豆清单色号行或引导页色号条切换，再点同一色取消。高亮时非选中色格子在 `drawCells` 阶段用 `dimmedFill` 混向纸色 88%，`drawLabels` 跳过其色号与已完成深色覆盖；选中色、空格、坐标、格间虚线、5×5 粗线、逐行红框均不受影响。`pattern` 变化或换图纸后若该色号已不在 `cells` 中，`useEffect` 自动清除高亮，不留全淡图纸。引导页色号条按 `progress` 显示该色剩余颗数，点格标记完成会联动减少。

**引导页定位与编辑现状**：`GuideView` 以按色号为主流程，逐行推进已移除；局部状态 `board` / `onlyBoard` / `hideCompleted` 分别是当前板索引、只看当前板、隐藏已完成。`splitBoards` 得到板矩形，`focusBoard` 传给 `drawGrid` 画红色板框，`dimOutsideBoard` 触发板外淡化。单板图纸不显示板切换。`App.tsx` 的 `replaceColour(from, to: string | null)` 调用 `core/pattern.ts` 的 `replaceCode` 一次性替换某色号全部格子，进 50 步撤销栈；`to = null` 表示「全部留空（不放豆）」，弹窗中「全部留空」按钮直接传 `null`，换成色号时传目标色号字符串。留空后 `patternStats` 的空格数增加、总豆数减少，用量表与导出即时重算（`tests/render.test.ts` 有统计一致性断言）。替换后若原高亮色号已不在 `cells` 中，`highlightCode` 的失效 effect 自动清除高亮。`exportPdf(range?)` 经 `clampBoardRange` 钳制后把板切片传给 `render/pdf.ts`，页眉仍用全局板号；板数 > 12 时界面提示分批。

**比例与尺寸推荐**：`recommendGridSize(imageW, imageH)` 以默认 29×29 的 841 格为用豆量基准，按精确比例先算宽再推高（1:2 → 21×42，2:1 → 41×21，1:1 → 29×29），与「锁定原图比例」输入联动公式完全一致。`lockRatio` 默认开启，改宽时高按 `sourceRatio` 联动，反之亦然；关闭后可自由输入。上传新图会重置推荐值，导入工程文件则 `sourceRatio=null`（无原图可锁）并视为已有图纸。

**去背景回退状态**（`App.tsx`）：`source` 为当前工作图，`originalSource` 保存去背景前的 `ImageData` 快照，`segmentApplied` 标记是否已应用。上传新图时快照设为该图、`segmentApplied=false`；抠图成功时仅在未应用过的情况下保存快照（避免二次抠图把快照覆盖成已抠图版本），然后替换 `source` 并置位；点「恢复原图」用快照的**新 `ImageData` 副本**写回 `source` 触发重新量化，清空编辑历史并复位标记。`dirty` 时回退同样弹二次确认。打开工程文件会清空快照，避免旧图回退按钮指向错误来源。抠图失败不改这两个状态。

**开关偏好持久化**（`src/core/preferences.ts`）：`localStorage` 键 `wedou.toggle-preferences` 只存 7 个布尔旗标——锁定原图比例、透明区留空、自动抠纯色背景、去掉孤立单颗豆、合并小色块、保留细线细节、色彩抖动；不存宽/高/最多颜色数、色板、豆径，也不上传云端。页面初始化时 `withTogglePreferences(DEFAULT_PARAMS, prefs)` 只覆盖开关字段，`lockRatio` 单独恢复；之后仅在用户显式切换开关（`isTogglePatch` / `changeLockRatio`）时写回。上传新图只重置推荐宽高，不动偏好；`openPattern()` 用工程文件自带的 `params` 整体覆盖当前参数，但不写偏好，所以打开旧图纸不会反向改写用户偏好，刷新后仍回到偏好值。`autoBackground` 与 `backgroundTolerance` 双向映射（开→`DEFAULT_BACKGROUND_TOLERANCE`、关→`0`），`detailPreserve` 缺失按开处理。读取时逐字段只接受 boolean，坏 JSON / 缺字段 / 类型错误 / 存储被禁用或配额满都静默回退出厂默认；多标签页后写者覆盖，不做 `storage` 事件同步。

| 情形 | 现行为 |
|---|---|
| 上传图片后 | 只解析、分析比例并推荐尺寸，不出图；显示待生成卡片与「生成图纸」按钮 |
| 生成前改参数 / 切色板 | 不触发转换；生成之后才恢复实时重算 |
| 长宽比非 1:1 | 按约 841 格基准推荐保持比例的宽高；锁定比例默认开，改一边另一边联动 |
| 上传第二张图 | 清空上一张图纸、重置 `generated=false` 与推荐尺寸，回到待生成 |
| 非图片文件 | 明确提示「请选择图片文件」 |
| 原图 >20MB 或 >4000px | 降采样并提示 |
| 网格 >200×200 | 输入框上限 200，后端上限 300 |
| 全透明图 | 该格为 `null`，用量表显示「暂无用豆」 |
| 渐变 / 四角不同色的背景 | 不猜背景，整图照常出豆；即使手动打开「自动抠纯色背景」也不会误删主体 |
| 纯色背景 + 打开自动抠背景 | 只删连到画面边缘的背景格；主体内部同色区域（白衣服、高光）保留 |
| 细线 / 高光细节 | 面积小但与主色对比强、且连成线的少数派优先保留；零散噪点不保留 |
| 色数超上限 | 稀有色合并到最接近的常用色，并提示合并数量 |
| 色卡数据异常 | 抓取脚本按色数校验，失败即以非零码退出 |
| AI 模型/CDN 不可用 | 提示「智能去背景不可用…可用橡皮手动擦除」，图纸保留 |
| localStorage 配额满 | 静默跳过写入，内存副本本次会话仍可用 |
| 云端 409 | 提示「云端版本较新，本地副本已保留」 |
| 未登录 / 登录态过期 | 本地草稿继续可用，登录按钮可用 |
| 忘记密码 | 凭注册时的一次性恢复码重置；成功后生成新码、旧码立即作废 |
| 写入中断 / 误删 | SQLite 原子 rename，配合 6 小时自动快照（保留最近 10 份） |
| 恢复码错误或缺失 | 返回 400「用户名或恢复码不正确」，不泄露用户是否存在 |
| 偏好存储为空 / 损坏 / 被禁用 | 7 个开关逐字段回退出厂默认，生成图纸不受影响 |
| 打开旧图纸后刷新 | 打开时显示图纸自带的开关，偏好不被改写；刷新后回到用户偏好 |
| 切换账号 | 本地草稿按账号分桶，不会把上一个账号的图纸带进新账号的图纸仓库 |
| 市集为空 / 搜索无结果 / 后端不可用 | 分别显示空态、无匹配态、错误态 + 重试；仓库的本地图纸不受影响 |
| 匿名访客进市集 | 可浏览、可搜索、可读详情；`shared` 为空，另存/分享/撤销提示登录 |
| 发布「未命名图纸」或非法缩略图 | 前端拦截 + 服务端 400，不落库 |
| 撤销他人的市集条目 | 403，不删数据 |
| 点「删除」图纸 | 先弹二次确认（文案带图纸名、说明不可恢复），取消 / Esc 不改动任何数据；确认后才同时移除本地草稿与云端图纸 |

**图纸仓库 / 市集状态**：`App.tsx` 的 `View` 为 `studio / guide / library / market`。仓库数据来自 `mergedLibrary(drafts, cloud)`；本地草稿按账号分桶（`wedou.drafts.<userId>`，未登录用 `wedou.drafts`），首次登录把未登录草稿迁移到该账号桶并同步云端，避免切换账号串图；仓库按名称在前端过滤。市集由 `MarketView` 自行分页拉取 `api.listMarket`（搜索防抖 200ms），详情走 `api.getMarketItem`，另存用 `createPattern` 生成新 id 与全新 `progress` 的独立副本。发布/撤销都会刷新 `marketShared`（`sourceId → marketId`）与 `marketRefresh`，仓库卡片据此显示「已分享到市集」或「分享到市集」。预览图由 `thumbFor` 按色号降采样生成 PNG dataURL（最长边 200px、纯色块、不写色号），仓库实时生成并缓存，市集在发布时把 dataURL 存入 `market_items.thumb`。静态版或后端不可用时隐藏市集入口、禁用分享按钮。

**背景判定参数**：`backgroundTolerance` 默认 `0`（不猜背景），UI「自动抠纯色背景」打开时取 `DEFAULT_BACKGROUND_TOLERANCE = 18`。旧工程 JSON 中带 `18` 的图纸导入后走新逻辑：更准，但渐变背景不再被当成可抠背景。判定分两步——`flatCornerBackground` 要求四角颜色彼此接近，否则整体放弃；`markBackgroundCells` 从网格四边连通漫延，只标记「连到画面边缘且颜色接近基准」的格子。透明由像素 alpha 独立决定，两者互不干扰；关闭「透明区留空」时背景剔除同样不启用。

**细节保护参数**：`detailPreserve` 为可选布尔，默认开（旧工程 JSON 缺该字段时也视为开），UI「保留细线细节」可关闭；抖动路径走连续 RGB，不参与此策略。`pickDetail` 要求少数派同时满足：占比 ∈ [`DETAIL_MIN_RATIO` 0.12, `DETAIL_MAX_RATIO` 0.4)、与主色 CIEDE2000 色差 ≥ `DETAIL_MIN_DELTA_E` 25、格内像素形成 ≥ `DETAIL_MIN_CLUSTER` 3 的 8 邻域连通块；`connectedDetailMask` 再要求这些细节格子在网格上连成 ≥ `DETAIL_MIN_CELL_CLUSTER` 3 格，孤立一两格退回多数票。`w*h < 9` 的小图纸不做格子级过滤。

## 7. 导出规格

- **PDF**：jsPDF 动态加载，A4 纵向，边距 12mm，格子 6.4mm（29 格 = 185.6mm）。每块 29×29 板一页，页内含板编号、`R… / C…` 全局坐标、**格内直接写色号**（2–3 字符 4.8pt、4 字符 4.2pt）、0.8mm 不透明深色 5×5 实线、每颗豆之间的格间虚线、每色号颗数。**中文图纸标题**由 `renderTitleImage()` 用浏览器系统字体以 3 倍分辨率渲染成 PNG 位图后 `addImage` 嵌入：覆盖任意汉字（含生僻字）、无需分发字库、PDF 体积几乎不变，代价是该行不可选中/搜索；纯 ASCII 标题仍走 jsPDF 原生可选文字。坐标、色号、统计等标注保持 ASCII，因为 jsPDF 内置字体无中文字形。
- **PNG**：`renderPatternPng`，格子 **32px**，格内色号字号 ≥ `cell*0.5`、字重 700，含坐标、5×5 粗实线、每颗豆之间的格间虚线、用量表（色块 / 色号 / 颗数 / 占比）与统计，整图单文件。画布高度按 `CHART_TOP + 网格 + TABLE_GAP + 表尾` 计算，避免图例行被裁掉。
- **拼接示意（多板图纸）**：每页右上角画一张小方块图（`assemblyMapLayout`），按整张图的板行列数铺满所有板，当前页那块填橙红并标编号，其余空心；标题行写 `ASSEMBLY MAP NxM | THIS PAGE K`。只在板数 > 1 时出现，位置固定在页眉右侧、网格上方（`y=8` 起，整体落在网格列坐标标签 `top-2` 之上），不与坐标挤在一起。单板图纸不画。
- **工程 JSON**：`serialize(pattern)`，可由图纸库导入。

空格在两种图纸里都画成浅底 + 小圆点，并在图例注明 `EMPTY CELLS = NO BEAD`。

**导出不受任何交互态影响**：`renderPatternPng` 用固定常量 `PNG_GRID_OPTIONS`（只有 `cell` / `showCodes` / `showCoordinates`），`exportPatternPdf` 的签名不含交互态，`App.tsx` 也只传 `pattern`。按色高亮、按板淡化、隐藏已完成都不进入导出：高亮态下导出的 PNG 与全彩态逐字节一致（2026-11-05 浏览器实测），PDF 同样生成完整图纸。交付标准第 6 条的「三处一致」针对导出图纸本身；预览中的淡化与不写色号属于屏幕交互态，不属于导出规格。`tests/render.test.ts` 锁定 `PNG_GRID_OPTIONS` 的字段集合，防止交互态被误加进导出。

**格内标记与 5×5 分块**：图纸只有**色号**一套标识（MARD `A1`/`C10`、Perler `P01`、Hama `H01`、Artkal `S01`），单字符符号体系已移除。格内文字按字符数自适应字号（≥ `cell*0.5`、字重 700），预览格子小于 `MIN_CODE_CELL = 20` 时不写字。`GRID_BLOCK = 5`：预览、PNG、PDF 统一每 5 格一条不透明深色粗实线，PDF 按**全局** 5 格边界对齐、跨板连续；行列坐标标 5/10/15…。图纸只有两级线型——**粗实线分 5×5 大块，格间虚线分大块内的每一颗豆**；禁止对角斜线 / X 形线。用量表第 4 列显示占比。

**绘制层次**：格子底色与空格圆点 → 格间虚线（整张网格一次画完，dash 相位对齐、不重复描共享边）→ 色号 → 5×5 粗实线 → 高亮板框。虚线只在格子边界、文字在格子中心，互不干扰，无需文字底衬。按色高亮 / 按板淡化 / 隐藏已完成统一由 `isSuppressed` 判定，淡化发生在**底色层**、色号与进度覆盖的跳过发生在 `drawLabels`，不新增蒙层或第三级线型；逐行红框已移除，红框只用于当前 29×29 板。PDF 同样按「填充 / 虚线 / 色号 / 粗线」四遍绘制。具体视觉下限见 `.codebuddy/rules/拼豆图纸交付标准.mdc`。

## 8. 色卡数据

`src/data/palettes.json`：来源 bitbead.app 公开色卡页，抓取日期见文件内 `fetchedAt`。7 套共 1406 色（221 / 291 / 117 / 89 / 176 / 221 / 291）。`scripts/fetch-palettes.mjs` 从 Next.js RSC 负载提取 `code/name/hex` 三元组，并校验与页面 `numberOfItems` 一致；请求间隔 400ms。2026-11-05 实测新增 Artkal Mini 221（`MA1` 起）与 COCO 291（`E02` 起）后，原有 5 套数据逐字节未变。

**DMC 未纳入**：`/en/colors/dmc` 虽然返回 200，但它是 HTML 表格形式的「绣线色号 ↔ MARD/Perler/Hama 近似豆号」对照表（页面自述 *convert a bead chart to a stitch chart and back*），色号买不到对应的拼豆；数据字段也不是 `code/name/hex` 三元组。按「色号必须能直接买豆」的原则排除，不为凑数编造色值。

**默认色板为 MARD 221**（`DEFAULT_PALETTE_ID`，2026-11-05 由 MARD 291 调整）；用户仍可切到 MARD 291 / Perler / Hama / Artkal / Artkal Mini / COCO。已保存的本地草稿与云端图纸各自记录 `paletteId`，打开时保持原色板不变。

HEX 为参考值，不等同实物色；界面多处明示，图纸以色号为唯一标识。`duplicateCodes()` 检出 4 组「同色不同号」（MARD 291 的 `Q4/R11`、Artkal 的 `S18/S94` 与 `S82/S155`、Artkal Mini 的 `MH1/MH2`），色号搜索列表会告警并把重复项画成虚线边框、悬停显示同伴色号；抓取脚本也会打印重复告警。生成图纸时两条分支都会统计 ΔE>10 的近似替代格数（非抖动按胜出色号的加权平均 ΔE，抖动按每格代表色 ΔE），界面在预览上方提示用户核对色号。

`segment.ts` 支持 `VITE_BG_MODULE_URL`（模块 ESM 地址）与 `VITE_BG_MODEL_BASE`（自托管 ONNX 模型目录）两个环境变量；留空则走 jsDelivr CDN。这样将来把约 40MB 模型放到任意静态源即可，无需改代码，也不必把模型塞进仓库。

## 9. 前端规范落地

CSS 全部走 `styles.css` 的变量体系（`--font-size` 基准、语义色、间距/圆角/阴影 token）；图标只用 lucide-react；二元状态用 Toggle Switch；色号选择（最多 291 色）用带搜索列表，并对同色不同号给出告警；列表表头与数据行共用 `.table-head` / `.table-row` 列模板；弹窗统一 `.modal-mask` 基类，子级用 `.nested` 提高层级；所有可点击元素有 hover；顶栏在 900px / 560px 两档断点重排，登录入口在手机端仍可见。

**图纸视口**：`.canvas-scroll` 高度 `min(70vh, 860px)`（移动端 55vh），canvas 默认按 `cell` 原生尺寸渲染并双向滚动，**不再被 `max-width: 100%` 强制压缩**；仅「适应窗口」态给 `.canvas-scroll.is-fit` 加 `max-width: 100%` 并关闭 `image-rendering: pixelated`。缩放档位 `[8,12,16,22,30,42] px/格`，按图纸宽度自动选默认档（≤29→22，≤60→16，≤120→12，更大→8），宽度变化时重置。全屏态用 `position: fixed; inset: 0` 脱离父级 Grid，自身用 `grid-template-rows: auto minmax(0,1fr)` 让工具栏与画布处于同一布局系统，不混用 absolute；Esc 监听在 `fullscreen` 为真时挂载、为假时移除。`cellFromPoint` 用 `rect.width / 逻辑宽度` 换算比例，CSS 缩放下点击仍精确。
